# 09 开发任务

## 给开发代理

- **开工前**：读 [文档索引](../README.md)、[总体设计](../DESIGN.md)、[01-architecture](01-architecture.md)，再读任务里“参考”列出的文档。
- **完成标准**：任务的验收标准逐条满足；相关测试、lint、类型检查全部通过；实现和文档不一致时，先改文档并在 PR 里说明原因。
- **提交方式**：一个任务一个分支，命名 `wp<编号>-<简述>`；PR 描述逐条列出验收标准对应的证据（测试名、命令输出或截图）。
- **密钥**：代码、测试、文档里只出现变量名和占位符；测试用的假密钥放在 fixtures 里，并确保会被密钥扫描拦下。
- **文档没覆盖的决定**：选最简单、以后容易改的做法，在 PR 里列出来。
- **原型**：`prototype/` 是交互参考，页面结构、文案和交互细节照它做；代码不直接复用。

## MVP 任务

### WP0 工程骨架
- 参考：[01-architecture](01-architecture.md)
- 产出：pnpm workspace（`apps/web`、`apps/worker`、`packages/shared`、`tools/*`）；TypeScript strict、ESLint、Prettier；`ci.yml`；`pnpm dev` 能同时启动前端和 Worker。
- 验收：
  - 全新克隆后 `pnpm install && pnpm lint && pnpm typecheck && pnpm test` 全部通过。
  - `pnpm dev` 启动后，浏览器打开前端地址看到占位页，`/api/health` 经代理返回 `{"ok":true}`。
  - CI 在 PR 上运行并通过。

### WP1 shared 核心库
- 参考：[02-data-model](02-data-model.md)、[04-frontend](04-frontend.md#搜索)、[05-security](05-security.md#密钥扫描)
- 产出：全部实体的 Zod schema 与类型；密钥扫描；搜索与高亮；变量解析与替换；快速记录转换；Markdown 序列化；安装清单生成；原型数据转换。
- 验收：
  - 每个 schema 覆盖 [02](02-data-model.md) 中的全部约束，每条约束至少一个通过用例和一个失败用例。
  - 密钥扫描每条规则有正例和反例，反例覆盖全部占位符写法。
  - 搜索用原型的 21 条示例数据复现原型行为：查询 `hook` 时排第一的是 Hook 类型条目，查询 `playwright` 时第一是 Playwright MCP。
  - 序列化是确定性的：同一输入两次输出逐字节相同；片段含三个反引号时围栏自动加长。
  - 原型转换把 `prototype/data.js` 的内容转成合法的导入数据（21 条条目、3 个环境）。

### WP2 数据库迁移与种子数据
- 参考：[02-data-model](02-data-model.md#表结构)
- 产出：`0001_init.sql`（含内置类型和平台）；`seed.json`；`pnpm seed`；Drizzle 表定义。
- 验收：
  - 空库执行全部迁移后再导入种子数据，没有报错；条目数 21、环境数 3。
  - 迁移测试验证同一类型下重复的 `slug` 会被拒绝，删除后可以重用。

### WP3 鉴权中间件
- 参考：[05-security](05-security.md#jwt-校验)
- 产出：JWT 校验、身份识别、角色映射、按路由的权限检查、本地开发身份。
- 验收：
  - 测试覆盖：缺少 JWT 返回 401；签名错误、`aud` 不符、已过期都返回 401；邮箱不在白名单返回 403；各角色访问表外接口返回 403。
  - `ENVIRONMENT=production` 时，设置 `DEV_AUTH_EMAIL` 也不会跳过校验。

### WP4 条目、环境、字典、设置接口
- 参考：[03-api](03-api.md)、[02-data-model](02-data-model.md#写入规则)
- 产出：条目增删改查、`PATCH`、修订查询与恢复、环境与成员关系、安装清单、类型、平台、标签改名、整理规则。
- 验收：
  - 每次写入在同一个 batch 里写实体、修订（更新和删除时）和变更日志；用测试断言三者的行数。
  - 过期的 `If-Match` 返回 409，`details.current` 是最新版本；缺少 `If-Match` 返回 428。
  - 含密钥的写入返回 422 `secret_detected`，响应里不出现原文。
  - 删除环境后，条目仍在，成员关系消失。

### WP5 同步、快速记录、导入导出接口
- 参考：[03-api](03-api.md#同步)、[02-data-model](02-data-model.md#导出格式)
- 产出：`/api/sync`、`/api/capture`（含幂等）、`/api/export`、`/api/import` 三种模式。
- 验收：
  - 从 `since=0` 开始反复同步，直到 `hasMore=false`，得到的数据与 `/api/export` 一致；之后每次写入都能在下一次增量同步中拿到，删除以 ID 形式出现。
  - 同一个 `Idempotency-Key` 提交两次快速记录，只生成一条条目，两次响应相同。
  - 导出后以 `replace` 模式导入，再次导出，两份文件除 `exportedAt` 外完全相同。
  - `prototype` 模式导入原型导出的 JSON，得到 21 条条目、3 个环境。

### WP6 前端骨架与本地数据层
- 参考：[04-frontend](04-frontend.md#状态与离线同步)
- 产出：Vue 应用骨架、路由、布局组件（侧栏、顶部栏、底部导航）、API 客户端、Dexie 库、同步引擎（拉取、`outbox` 上传、退避重试、Web Locks、BroadcastChannel）。
- 验收：
  - 单元测试模拟接口：离线时写入进入 `outbox`，恢复联网后按顺序上传；409 进入冲突状态；422 撤销本地修改。
  - 两个标签页同时打开时只有一个在同步，另一个在对方写入后自动刷新数据。

### WP7 前端共用页面、结构 1 与外观设置
- 参考：[04-frontend](04-frontend.md#页面规格)、[08-ui-spec](08-ui-spec.md#切换与保存)、原型
- 产出：结构 1（三栏）的工作台与条目页；各结构共用的新建与编辑、环境（列表、详情、编辑、添加条目）、数据与设置、命令面板、手机记录面板、冲突对话框、提示条；三套配色的浅色、深色令牌，外观面板与外观设置。
- 验收：
  - Playwright 端到端测试在桌面（1440×900）和手机（390×844）两种视口下，覆盖原型已验证过的全部行为：快速记录、命令面板搜索与 `Ctrl+Enter` 复制、状态修改、复制为 Markdown、提示词变量填写后复制、新建与编辑与删除条目、生成安装清单、环境的新建/编辑/删除/添加与移出条目、手机记录面板、平台筛选、切换列表范围时清空筛选、用户内容被转义。
  - 桌面端同一列表内切换条目时，列表元素不重新创建（测试断言同一 DOM 节点）。
  - 开启“减少动态效果”时没有过渡动画。
  - 无障碍自动检查（如 axe）在主要页面没有严重问题。
  - 在外观面板里切换配色和深浅色后立即生效，刷新后保持；首屏直接以保存的外观渲染，不出现跳变。结构选项随 WP7A–WP7D 完成逐个加入。

### WP7A 结构 2 卡片墙
- 参考：[08-ui-spec](08-ui-spec.md#界面结构)、原型 `?layout=gallery`
- 验收：
  - 首页卡片数等于未弃用条目数，按类型分组；点顶部类型标签后只显示该类型。
  - 卡片上的复制按钮：片段没有变量时直接复制；有变量时打开详情让用户填写。
  - 详情在右侧抽屉打开，按 `Esc`、点遮罩、点“关闭”都能关闭，关闭后回到原来的列表。
  - 手机上单列卡片，详情整页显示，顶部有返回按钮。

### WP7B 结构 3 搜索优先
- 参考：[08-ui-spec](08-ui-spec.md#界面结构)、原型 `?layout=launcher`
- 验收：
  - 进入首页时搜索框自动获得焦点；输入 `hook` 时第一条结果是 Hook 类型条目。
  - 方向键切换选中项，右侧预览同步更新；`Enter` 复制选中条目的第一个片段，`Ctrl/⌘+Enter` 打开编辑，`Esc` 清空搜索。
  - 没有结果时按 `Enter`，以输入内容为名称新建条目。
  - 手机上点结果打开整页详情。

### WP7C 结构 4 看板
- 参考：[08-ui-spec](08-ui-spec.md#界面结构)、原型 `?layout=board`
- 验收：
  - 按状态分组时，五列卡片数之和等于条目总数；把卡片拖到另一列，状态改变并写入修订。
  - 在待整理列顶部的输入框里回车，即新建一条待整理条目。
  - 按环境分组时列数等于环境数加 1（多出的一列是“未加入环境”），按类型分组时列数等于类型数；这两种分组下卡片不能拖动。
  - 点卡片在抽屉里打开详情；手机上每列占一屏宽，左右滑动切换列。

### WP7D 结构 5 知识库
- 参考：[08-ui-spec](08-ui-spec.md#界面结构)、原型 `?layout=docs`
- 验收：
  - 侧栏目录按类型列出全部未弃用条目，当前条目高亮；收起的类型在切换条目后保持收起。
  - 文档页右侧有属性栏，可以直接改状态、置顶、复制为 Markdown；点“本页目录”滚动到对应小节，地址不变。
  - 手机上目录单独一页，文档页的属性栏在正文上方。

### WP7A–WP7D 共同验收
- 5 种结构 × 3 套配色 × 浅深色，共 30 种组合，每种都能打开工作台和同一个条目的详情，控制台没有报错。原型已有同样的自动检查，可以照搬思路。
- CI 为这 30 种组合各生成一张桌面截图，另为每种结构生成一张手机截图，作为视觉回归基线；改动引起截图变化时，在 PR 里附上对比图。
- 切换结构时地址不变，当前打开的条目仍然打开。

### WP8 PWA

- 验收：能添加到手机主屏并以独立窗口打开；断网后重新打开，仍能浏览和搜索已缓存的条目；发布新版本后出现“有新版本，刷新后生效”的提示。

### WP9 部署流水线与上线
- 参考：[06-ops](06-ops.md#首次部署)

- 验收：首次部署表格里的每一步都达到完成标准，冒烟检查全部符合预期。

### WP10 备份流水线
- 参考：[06-ops](06-ops.md#备份)、[02-data-model](02-data-model.md#markdown-镜像)
- 产出：`tools/backup`（`check-export`、`to-markdown`）、`backup.yml`。
- 验收：
  - 手动触发一次后，`ai-kit-data` 出现 `entries/`、`stacks/`、`export.json`，坚果云出现当天的加密快照。
  - 数据无变化时再触发一次，不产生新提交。
  - 导出条目数为 0 时，任务失败，镜像保持不变。
  - 用快照在本地走一遍恢复流程，条目数一致。

## 阶段 2 任务

### WP11 历史版本界面
- 参考：[04-frontend](04-frontend.md#页面规格)（详情中的历史版本）

### WP12 字典、标签与整理规则管理界面

## 阶段 3 任务

### WP14 提案：后端与待确认页
- 参考：[07-mcp-scanner](07-mcp-scanner.md#提案)、[03-api](03-api.md#提案)
- 验收：
  - 四种提案都能创建、接受、拒绝；接受后条目按正常写入规则落库，修订里记录提案 ID。
  - 目标条目在提案之后被改过时，接受返回冲突，界面显示差异。
  - 批量接受 50 条提案，其中一条校验失败时，其余 49 条成功，失败的那条显示原因。

### WP15 MCP 端点
- 参考：[07-mcp-scanner](07-mcp-scanner.md#mcp-端点)
- 验收：
  - 用 Claude Code 按示例命令接入后，`/mcp` 里能看到全部工具；让它“搜索我档案里的 MCP”能返回正确结果。
  - `capture` 生成待整理条目；`propose_change` 生成提案且不直接修改条目；含密钥的草稿被拒绝，并返回可读的原因。
  - 用 `backup` 令牌调用 `/mcp` 返回 403。

### WP16 本机扫描器与扫描上传
- 参考：[07-mcp-scanner](07-mcp-scanner.md#本机扫描器)
- 验收：
  - 对 fixtures 目录扫描的结果与预期快照一致；输出中不出现任何 fixtures 里的假密钥原值。
  - 白名单外的文件（如 `auth.json`）即使存在也不会被打开（测试中用文件访问记录断言）。
  - 空档案上第一次上传生成的全是 `create` 提案；全部接受后立即再扫描一次，不再生成提案；删除一项本机配置后再扫描，生成一条“移出环境”的提案。
